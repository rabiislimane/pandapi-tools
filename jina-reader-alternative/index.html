Jina Reader alternatives: when one URL at a time isn't enough

Putting https://r.jina.ai/ in front of a URL is the fastest way to get Markdown for an LLM, and it's free to try. It's one URL per request, though. Once you need a whole docs site, a sitemap, chunks or a nightly sync, you're writing a crawler around it.

What Jina Reader does well

  • No setup: curl https://r.jina.ai/https://example.com returns Markdown.
  • Free without a key at 20 requests a minute; a free or paid key raises it to 500 requests a minute. Paid use is billed by output tokens.
  • Handles JavaScript pages and PDFs by URL.

Switching takes one call

curl -X POST "https://api.apify.com/v2/acts/blueberry_rainstorm~web-page-to-markdown/run-sync-get-dataset-items?token=$APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "urls": [
    {
      "url": "https://docs.example.com/"
    }
  ],
  "crawl": true,
  "crawlScope": "path",
  "maxPages": 500,
  "chunkSize": 800
}'

Questions

Is Jina Reader free?

You can call r.jina.ai without a key at 20 requests a minute. With a key the limit rises to 500 a minute, and usage is billed by output tokens after any free allowance.

Can Jina Reader crawl a whole website?

Not by itself: it converts one URL per request. You need your own crawler, or an API that crawls, such as Pandapi Website to Markdown or Firecrawl.

What's a good alternative for RAG?

One that returns chunks with their heading path and a source link, so answers can cite the section. Pandapi Website to Markdown does that at $1 per 1,000 pages.
